# Amhra Dashboard — API Usage

All `/api/*` requests are proxied to the Amhra bot's Express server via the rewrite in
[next.config.mjs](../next.config.mjs) (`/api/:path*` → `${API_URL}/:path*`). The dashboard never
talks to the bot server directly from the browser except through this proxy.

## Authentication schemes

Three kinds of credentials exist, distinguished by the `Authorization` header format:

| Session type | Header format      | Source                                                    |
| ------------ | ------------------ | --------------------------------------------------------- |
| `admin`      | `Basic <password>` | Admin password entered on `/login`, stored in `localStorage.key` |
| `bearer`     | `Bearer <token>`   | Discord OAuth token minted by `/api/register`, delivered via URL hash on `/dashboard#<token>`, stored in `localStorage.bearer` |
| `visitor`    | `<token>` (raw, no prefix) | One-time link `/dashboard/<base64({guildId, auth})>` generated by the bot |

Bearer sessions are restricted: the Logs and Message tabs are disabled, and the Terminate /
Reload Commands / Reload Settings actions are hidden. Visitor sessions can only use the song
dashboard for their single guild.

## Endpoints

### Session

| Endpoint | Method | Auth | Body | Used for |
| --- | --- | --- | --- | --- |
| `/api/new` | GET | Basic or Bearer | — | Login / token validation. `ok` = valid credentials. |
| `/api/logout` | GET | Basic | — | Logout (fire-and-forget). |
| `/api/live` | POST | raw visitor token | `{ guildId }` | Visitor link validation; polled every **5 s** while a visitor page is open. Non-`ok` invalidates the page. |

### Administration

| Endpoint | Method | Auth | Body | Used for |
| --- | --- | --- | --- | --- |
| `/api/action` | POST | Basic | `{ action: "exit" \| "addAuth" \| "reload" \| "reloadSetting", guildId? }` | Terminate bot, reload commands, reload settings. |
| `/api/log` | GET | Basic | — | Log viewer; polled every **3 s** (SWR key `/api/log`). Response `{ content: Log[] }`. The client strips a leading `[VOICE]`/`[DELETE]`/`[EDIT]` tag from `message` into `extraType` and reverses the array (newest first). |
| `/api/guildIds/all` | GET | Basic (admin) | — | Guild picker on the Message tab. Response `{ content: { id, name }[] }`. |
| `/api/messages/:guildId` | GET | Basic (admin) | — | Message viewer (SWR key `/api/messages/${guildId}`). Response `{ content: Channel[] }`. |

### Music player

| Endpoint | Method | Auth | Body | Used for |
| --- | --- | --- | --- | --- |
| `/api/playingGuildIds` | GET | Basic or Bearer | — | Guild picker on the Song tab (SWR key `/api/playingGuildIds`). Response `{ content: { id, name }[] }`. |
| `/api/song/get/:guildId` | GET | any scheme | — | Player state (`SongReply`); polled every **2 s** (SWR key `/api/song/get/${guildId}`). All mutations revalidate this key. |
| `/api/song/edit` | POST | any scheme | `{ action, guildId, detail? }` | Every player mutation. See action table below. |
| `/api/search` | POST | any scheme | `{ query }` | Resolve a free-text query to a YouTube video when the Add Song input is not a YouTube URL. Response `{ url, title, durationInSec }`. |
| `/api/getVideoDetail` | POST | any scheme | `{ url }` | Video metadata for Now Playing / queue / history cards. Fetched with `cache: 'force-cache'`; SWR-keyed by the video URL. |

### `/api/song/edit` actions

The `detail` payload key depends on the action:

| Action | `detail` |
| --- | --- |
| `pause`, `resume`, `skip`, `stop`, `quit`, `mute`, `unmute`, `skipSegment` | omitted |
| `addSong` | `{ url: string }` |
| `setTime` | `{ sec: number }` (rounded to whole seconds) |
| `removeSong` | `{ index: number }` |
| `setVolume` | `{ volume: number }` (0–1, 3 decimal places) |
| `setQueue` | `{ queue: { url: string, repeating: boolean }[] }` |
| `loop` | `{ loop: boolean }` |

### Next.js route handlers (this app's own API)

| Route | Behaviour |
| --- | --- |
| `GET /api/register?code=…` | Exchanges the Discord OAuth `code` by POSTing `{ code }` to `${API_URL}/register`; on success redirects to `${NEXT_PUBLIC_URL}/dashboard#<token>` (token travels in the URL hash, never as a query param); on failure redirects to `/`. |
| `GET /invite` | Redirects to `INVITE_LINK` (plain bot invite), falling back to `/`. |

### Environment variables

| Variable | Purpose |
| --- | --- |
| `API_URL` | Bot server base URL (server-side: rewrite proxy + register handler). |
| `NEXT_PUBLIC_URL` | Public origin used for OAuth redirects. |
| `NEXT_PUBLIC_INVITE_LINK` | Discord OAuth authorize URL used by `/discord` (client-side redirect). |
| `INVITE_LINK` | Plain bot invite used by `/invite` (server-side redirect). |
